### Justification for Area, Workspace, UserProfile in Entity Domain

Per 10_9 §4.1 and the Repository Inventory (Section 3 Aggregate Mapping), these models are scoped to the **same aggregate** as Entity:

- **Area**: Entities live within an Area within a Workspace. Area is a hierarchical classification that scopes Entity organization. The inventory states: *"Areas and workspace are scoped to the same aggregate (Entity lives within an Area within a Workspace)."*
- **Workspace**: Top-level container (singleton). All Entities are workspace-scoped. The workspace provides the multi-tenancy boundary.
- **UserProfile**: User identity scoped to the workspace. Entities and Areas are associated with user profiles.

### Justification for MemoryRelationship in RelationshipRepository

Per 10_9 §4.4 and Section 3 Aggregate Mapping:
- `RelationshipAggregate → RelationshipRepository`
- `MemoryRelationship Aggregate → RelationshipRepository (shared)`

Two distinct relationship aggregates (EntityRelationship and MemoryRelationship) are managed under one Repository. This follows the design principle that all relationship persistence is centralized.

### Where Existing Models Are Defined

All six models are defined in a single file:
- `backend/src/backend/shared/domain/memory_models.py`
- Exported via `__all__` at line 671-684.

## 5. Relationship Implementation

### Uniqueness

**EntityRelationship (`relationships` table):**
- **Primary Key:** `id` (UUID, auto-generated by caller)
- **Unique Constraint:** `uk_relationship_direction` = UNIQUE(`source_id`, `target_id`, `relationship_type`)
- **No uniqueness on (source_id, target_id) alone** — multiple relationship types between the same pair are allowed.
- **Check Constraints:**
  - `chk_no_self_relationship`: `source_id != target_id`
  - `chk_strength_range`: `strength` between 0.0 and 1.0
  - `chk_relationship_type`: 10 allowed types

**MemoryRelationship (`memory_relationships` table):**
- **Primary Key:** `id` (UUID, auto-generated by caller)
- **Unique Constraint:** `uk_memory_relationship_direction` = UNIQUE(`source_node_id`, `target_node_id`, `relationship_type`)
- **Check Constraints:**
  - `chk_no_self_memory_rel`: `source_node_id != target_node_id`
  - `chk_memory_rel_weight_range`: `contribution_weight` between 0.0 and 1.0
  - `chk_memory_relationship_type`: 4 allowed types

### Multiple Relationships Between Same Pair

**Yes, supported.** The unique constraint includes `relationship_type`, so the same source-target pair can have multiple relationships with different types (e.g., one "created_by" and one "related_to").

### Indexes

Indexes are defined in the DDL (09_Database_Physical_Design.md), not in the ORM models. The ORM models declare `UniqueConstraint` but BTREE indexes for query performance are handled by the DDL migration scripts.

| `relationships` | `workspace_id` | `workspace.id` | CASCADE |
| `relationships` | `source_id` | `entities.id` | CASCADE |
| `relationships` | `target_id` | `entities.id` | CASCADE |
| `memory_relationships` | `workspace_id` | `workspace.id` | CASCADE |
| `memory_relationships` | `source_node_id` | `memory_nodes.id` | CASCADE |
| `memory_relationships` | `target_node_id` | `memory_nodes.id` | CASCADE |

### Cascade Rules
- **Workspace deletion** cascades to: entities, areas, user_profiles, relationships.
- **Entity deletion** cascades to: relationships (source_id, target_id).
- **Area deletion** sets entity.area_id to NULL.
- **Self-references** (parent_entity_id, parent_area_id) use SET NULL.

### Delete/Update Behavior
- **Delete:** CASCADE for workspace-scoped children; SET NULL for optional relationships.
- **Update:** No explicit ON UPDATE rules defined. SQLAlchemy default behavior applies.

All FK strategies match GitHub HEAD (memory_models.py lines 422-660).

## 7. Alias Storage

### Current Implementation

Aliases are stored as a PostgreSQL `ARRAY(String)` column:

```python
aliases: Mapped[list[str]] = mapped_column(ARRAY(String), nullable=False, default=list)
```

- **Database Type:** `text[]` (PostgreSQL array of text)
- **Default:** Empty list `[]`
- **Nullable:** False
- **Access Pattern:** 
  - Full match: `aliases.contains([alias])` (ARRAY = ANY操作)
  - Partial match: `aliases.any(partial)` (ARRAY partial match)

## 8. UUID Implementation Review

### UUID Version Used

| ORM Model | UUID Version | Generation Method | Package |
|-----------|-------------|-------------------|---------|
| All models | **UUIDv4** (via `from uuid import UUID`) | Caller-provided (entity.id assigned before create) | Python stdlib `uuid` |

### UUID Generation Method

**No automatic UUID generation.** The `BaseRepository.create()` method expects the entity to already have an `id` attribute assigned. The repository does NOT generate UUIDs internally.

From `entity_repository.py` line 98-104:
```python
entity_id = getattr(entity, "id", None)
if entity_id is None:
    raise DomainIntegrityError(...)
return UUID(entity_id) if not isinstance(entity_id, UUID) else entity_id
```

The caller (Service layer or test code) is responsible for generating and assigning the UUID before calling `create()`.

### Package Used

Python standard library `uuid` module only. No `uuid7` package or third-party library.

### Python Version Assumed

Python 3.10-3.12 (per pyproject.toml classifiers). Current environment: Python 3.11.15.

### UUIDv4 vs UUIDv7 Conflict

**Fact:** The codebase uses Python's stdlib `uuid.UUID` type for all primary keys. No UUID version is enforced at the ORM level — the `id` column is `Mapped[Any] = mapped_column(primary_key=True)` with no type constraint.

**Conflict:** 10_9 §5.1 states *"UUIDv7 Generator — Time-ordered UUID generation"* as shared infrastructure requirement, and `types.py` line 22 declares `#: Primary key type — UUIDv7 throughout the project.` However, the implementation uses generic `UUID` (v4-compatible) with no v7 enforcement.

**Affected Files:** All 6 new files in D2.3 use `from uuid import UUID` from stdlib. No UUIDv7 library is imported or configured.

**Reason:** The UUID generator infrastructure (D2.1) was not yet implemented when D2.3 was developed. The architecture specifies UUIDv7 but the implementation defers to caller-provided UUIDs.
