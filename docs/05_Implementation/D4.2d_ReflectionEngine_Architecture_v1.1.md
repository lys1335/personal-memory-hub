## 1. Purpose Update

### 1.1 Scope Reduction

ReflectionEngine's scope has been **narrowed** to exclude Information Extraction.

**Previous Scope** (V1.0):
- Reflection semantic validation
- Reflection candidate evaluation
- **Fact extraction from evidence** ← REMOVED
- Knowledge evolution validation
- Reflection consistency
- Knowledge consolidation rules
- Reflection domain invariants

**Current Scope** (V1.1):
- Reflection semantic validation
- Reflection candidate evaluation
- Knowledge evolution validation
- Reflection consistency
- Knowledge consolidation rules
- Reflection domain invariants

### 1.2 New Boundary

## 2. Responsibility Update

### 2.1 What ReflectionEngine NOW Owns

ReflectionEngine owns **Reasoning** over Candidates:

| Capability | Description |
|------------|-------------|
| Memory Creation Decision | Should we create a new Memory at a higher level? |
| Merge Decision | Should we merge this candidate with existing memories? |
| Split Decision | Should we split this candidate into multiple memories? |
| Strengthen Decision | Should we strengthen an existing memory's confidence? |
| Refine Decision | Should we refine an existing memory's content? |
| Reject Decision | Should we reject this candidate? |

### 2.2 What ReflectionEngine NO LONGER Owns

| Capability | Moved To |
|------------|----------|
| Entity Extraction | EvidenceEvolutionEngine |
| Pattern Discovery | EvidenceEvolutionEngine |
| Evidence Aggregation | EvidenceEvolutionEngine |
| Evidence Chain Construction | EvidenceEvolutionEngine |
| Confidence Estimation | EvidenceEvolutionEngine |

### 2.3 Method Signature Update

```python

    """Domain engine for Reflection reasoning over Candidates."""
    
    async def reflect_pipeline(
        self,
        *,

            Dict with keys: proposals, entities, validation_passed, execution_log.
        """
```

**Key Change**: Input is now `candidates`, not raw evidence.

## 3. Component Update

### 3.1 Component Restructuring

**Previous Components** (V1.0):
1. FactExtractorComponent — LLM-assisted fact extraction
2. InterestAnalyzerComponent — Rule-driven interest trend analysis
3. ProjectionUpdaterComponent — Rule-driven proposal generation
4. ReflectionValidator — Domain invariant enforcement

**Current Components** (V1.1):
1. ~~FactExtractorComponent~~ — REMOVED (moved to EvidenceEvolutionEngine)
2. InterestAnalyzerComponent — Rule-driven interest trend analysis
3. ProposalGeneratorComponent — Rule-driven proposal generation
4. ReflectionValidator — Domain invariant enforcement

### 3.2 reflect_pipeline() Update

```python
async def reflect_pipeline(self, *, scope, candidates, provider):
    execution_log = []
    
    # Step 1: Analyze interest trends (unchanged)
    interest_trends = self._analyze_interest(candidates)
    
    # Step 2: Generate proposals (renamed from _generate_proposals)
    proposals = self._generate_proposals(candidates, interest_trends)
    
    # Step 3: Validate proposals (unchanged)
    validation_result = self._validate_proposals(proposals)
    
    return {
        "proposals": proposals,
        "entities": self._extract_entity_names(proposals),
        "validation_passed": validation_result.success,
        "execution_log": execution_log,
    }
```

## 4. Domain Rules Update

### 4.1 New Rule: Candidate-Centric Reasoning

> ReflectionEngine reasons over Candidates, not Evidence.

All decisions (Create/Refine/Split/Reject) are based on Candidate content and evidence_chain, not raw evidence.

### 4.2 Updated Rule: No Extraction

> ReflectionEngine does not extract information.

Entity extraction, pattern discovery, and evidence aggregation are EvidenceEvolutionEngine responsibilities.

### 4.3 Updated Rule: source_level Propagation

> ReflectionEngine must preserve source_level from Candidate.

```python
proposal["source_level"] = candidate.get("level", 1)
proposal["target_level"] = proposal["source_level"] + 1  # For Create/Strengthen
```

---

## 5. Domain Invariants Update

### 5.1 Evidence Requirement Invariant (Updated)

> Every Proposal must have complete evidence chain from Candidate.

**Before**: Evidence chain traced to Evidence items
**After**: Evidence chain traced to Candidate's evidence_chain

### 5.2 No Extraction Invariant (NEW)

> ReflectionEngine must not call LLM for extraction.

LLM calls in ReflectionEngine are for reasoning validation only, not information extraction.

## 7. Multi-Level Evolution

### 7.1 Level Propagation (Updated)

ReflectionEngine now correctly propagates source_level:

| Candidate source_level | Proposal target_level | MemoryNode level |
|------------------------|----------------------|------------------|
| 1 (Evidence) | 2 | 2 (Pattern) |
| 2 (Pattern) | 3 | 3 (Belief) |
| 3 (Belief) | 4 | 4 (State) |

### 7.2 Proposal Type Decision

```python
# In _generate_proposals()
source_level = candidate.get("level", 1)

if avg_confidence >= 0.8 and len(evidence) >= 3 and source_level < max_level:
    proposal_type = "Strengthen"
    target_level = source_level + 1
elif avg_confidence >= 0.6 and len(evidence) >= 2 and source_level < max_level:
    proposal_type = "Create"
    target_level = source_level + 1
elif avg_confidence >= 0.9:
    proposal_type = "Refine"
    target_level = source_level
else:
    proposal_type = "Split"
    target_level = source_level
```
