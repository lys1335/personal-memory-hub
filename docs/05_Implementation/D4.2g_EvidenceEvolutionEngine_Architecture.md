## 1. Purpose

### 1.1 Core Identity

EvidenceEvolutionEngine is the **Evidence Evolution Domain semantic owner**.

EvidenceEvolutionEngine is a stateless domain engine responsible for **Information Extraction** from Evidence to produce Candidate objects.

It owns:

- Entity Extraction
- Pattern Discovery
- Evidence Aggregation
- Evidence Chain Construction
- Confidence Estimation

EvidenceEvolutionEngine is a **Domain Engine**, not a persistence wrapper. It does not call databases directly. It operates on Domain Models provided by Repository.

### 1.3 Relationship with ReflectionEngine

| Aspect | EvidenceEvolutionEngine | ReflectionEngine |
|--------|------------------------|------------------|
| **Primary Responsibility** | Information Extraction | Reasoning |
| **Input** | Evidence / MemoryNode (L1) | Candidate |
| **Output** | Candidate | Proposal |
| **LLM Usage** | Yes (extraction) | Yes (reasoning) |
| **Database Access** | No (Repository only) | No (Repository only) |
| **State** | Stateless | Stateless |

**Key Distinction**:
- EvidenceEvolutionEngine transforms raw evidence into structured candidates (extraction)
- ReflectionEngine evaluates candidates and decides what to do with them (reasoning)

## 2. Responsibilities

### 2.1 Entity Extraction

EvidenceEvolutionEngine extracts entities from evidence:

- Identify named entities (person, organization, location, product, etc.)
- Extract entity attributes and relationships
- Normalize entity names (canonical form)
- Handle entity aliases and variations

**Input**: Evidence content (text)
**Output**: List of extracted entities with confidence scores

### 2.2 Pattern Discovery

EvidenceEvolutionEngine discovers patterns across evidence:

- Semantic clustering of similar evidence
- Frequency analysis of entity mentions
- Temporal pattern detection (if timestamps available)
- Cross-entity pattern identification

**Input**: List of evidence items
**Output**: Pattern candidates with supporting evidence groups

### 2.3 Evidence Aggregation

EvidenceEvolutionEngine aggregates evidence for candidate formation:

- Group evidence by entity/topic
- Calculate aggregate confidence
- Build evidence chains
- Detect evidence conflicts

**Input**: Individual evidence items
**Output**: Aggregated evidence groups with strength metrics

### 2.4 Evidence Chain Construction

EvidenceEvolutionEngine constructs evidence chains:

- Link evidence items to candidates
- Maintain traceability to source evidence
- Validate chain completeness
- Record evidence sources

**Input**: Aggregated evidence groups
**Output**: Evidence chains with source tracking

### 2.5 Confidence Estimation

EvidenceEvolutionEngine estimates confidence:

- Per-evidence confidence scoring
- Aggregate confidence calculation
- Confidence decay modeling (if applicable)
- Uncertainty quantification

**Input**: Evidence chains
**Output**: Confidence scores for candidates

## 3. Public Contract

### 3.1 Method Signature

```python
class EvidenceEvolutionEngine(EngineBase):
    """Domain engine for Evidence → Candidate evolution."""
    
    async def evolve(
        self,
        *,
        evidence: list[dict[str, Any]],
        provider: ReflectionProvider,
    ) -> EvolutionResult:
        """
        Execute evidence evolution pipeline.
        
        Args:
            evidence: List of evidence dicts with content, source, metadata
            provider: LLM provider for inference
            
        Returns:
            EvolutionResult with:
            - candidates: List of candidate dicts
            - entities: List of extracted entity names
            - execution_log: Processing log
        """
```

### 3.2 EvolutionResult Structure

```python
@dataclass
class EvolutionResult:
    candidates: list[dict[str, Any]]
    entities: list[str]
    execution_log: list[str]
    statistics: dict[str, Any]  # count, confidence_distribution, etc.
```

### 3.3 Candidate Output Format

Each candidate dict contains:

```python
{
    "id": UUID,                          # Generated by Service layer
    "entity_id": UUID | None,            # Associated entity
    "area_id": UUID | None,              # Associated area
    "content": str,                      # Structured content
    "candidate_type": str,              # "pattern" | "belief"
    "evidence_source": str,             # Source type
    "evidence_id": UUID | None,         # Primary evidence
    "evidence_chain": list[str],        # All evidence IDs
    "evidence_count": int,              # Number of evidence items
    "evidence_strength": float,         # Aggregated strength (0-1)
    "confidence": float,                # Estimated confidence
    "source_level": int,               # Source level (1 for Evidence)
    "status": str,                     # "candidate"
}
```

## 4. Internal Composition

### 4.1 Architecture Overview

```
EvidenceEvolutionEngine (Public Facade)
│
├── Extraction Capability      — Entity extraction from evidence
├── Clustering Capability      — Semantic clustering of evidence
├── Aggregation Capability     — Evidence aggregation per entity
├── ChainBuilder Capability    — Evidence chain construction
├── ConfidenceEstimator        — Confidence estimation logic
└── Validation Capability      — Candidate validation
```

### 4.2 Capabilities

#### Extraction Capability

- Extracts structured information from raw evidence
- Uses LLM for entity recognition and relationship extraction
- Applies rules for noise filtering

**LLM Prompt Goal**: Extract entities, attributes, and relationships from evidence text.

#### Clustering Capability

- Groups semantically similar evidence
- Uses rule-based similarity metrics
- Handles entity co-occurrence patterns

**No LLM** — Pure rule-based algorithm.

#### Aggregation Capability

- Aggregates evidence by entity/topic
- Calculates aggregate metrics
- Detects contradictions

**No LLM** — Pure rule-based algorithm.

#### ChainBuilder Capability

- Builds evidence chains
- Validates chain completeness
- Maintains traceability

**No LLM** — Pure rule-based algorithm.

#### ConfidenceEstimator

- Estimates confidence scores
- Aggregates per-evidence confidence
- Applies confidence decay rules

**No LLM** — Pure rule-based algorithm.

#### Validation Capability

- Validates candidate completeness
- Checks evidence chain integrity
- Enforces domain invariants

**No LLM** — Pure rule-based algorithm.

## 5. Domain Rules

### 5.1 Evidence Foundation Rule

> Every Candidate must have complete evidence chain.

- No Candidate without evidence
- Evidence must trace to original source
- Evidence chain cannot be broken

### 5.2 Information Extraction Rule

> EvidenceEvolutionEngine performs extraction, not reasoning.

- Extract entities, not infer beliefs
- Aggregate evidence, not evaluate truth
- Structure information, not make decisions

### 5.3 Level Propagation Rule

> source_level must be propagated from source to candidate.

- Evidence (L1) → Candidate with source_level=1
- MemoryNode (L2) → Candidate with source_level=2
- MemoryNode (L3) → Candidate with source_level=3

### 5.4 Entity Association Rule

> Candidates should be associated with entities when possible.

- Try to link to existing entity
- Create entity reference if none exists
- Record entity association in candidate

### 5.5 Confidence Propagation Rule

> Candidate confidence reflects evidence quality.

- Aggregate per-evidence confidence
- Apply aggregation formula (weighted average)
- Record confidence distribution

---

## 6. Domain Invariants

### 6.1 Evidence Completeness Invariant

> Every candidate must have at least one evidence item.

Violations result in candidate rejection.

### 6.2 Traceability Invariant

> Every candidate must trace back to original evidence.

Evidence chain must be complete and unbroken.

### 6.3 Level Consistency Invariant

> Candidate source_level must match source memory level.

L1 evidence → source_level=1
L2 pattern → source_level=2

### 6.4 No Reasoning Invariant

> EvidenceEvolutionEngine must not make reasoning decisions.

Only extraction and aggregation. No Create/Refine/Split decisions.

EvidenceEvolutionEngine uses LLM for:

- Entity extraction from unstructured text
- Relationship extraction
- Semantic clustering guidance (optional)

## 8. Service Integration

### 8.1 ReflectionService Orchestration

```python
class ReflectionService:
    async def reflect(self, ...):
        # Step 1: Acquire scope
        candidates = await self._acquire_scope(...)
        
        # Step 2: Evidence Evolution (NEW)
        evolution_result = await self._run_evolution_pipeline(candidates)
        
        # Step 3: Save candidates
        await self._save_candidates(evolution_result.candidates)
        
        # Step 4: Reflection (existing)
        proposals = await self._run_reflection_engine(...)
        
        # Step 5: Save proposals
        await self._save_proposals(proposals)
```

## 9. Multi-Level Evolution

### 9.1 Level Propagation

EvidenceEvolutionEngine supports multi-level input:

| Source Level | Source Type | Output source_level |
|-------------|-------------|---------------------|
| L1 | Evidence / Observation | 1 |
| L2 | Pattern | 2 |
| L3 | Belief | 3 |
| L4 | State | 4 |

### 9.2 Level-Specific Behavior

**L1 Evidence → Candidate**:
- Entity extraction focus
- Pattern discovery
- Evidence aggregation

**L2 Pattern → Candidate**:
- Cross-pattern analysis
- Belief candidate generation
- Pattern consolidation

**L3+ Belief → Candidate**:
- Belief refinement
- Belief consolidation
- State activation preparation

### 9.3 source_level Propagation

The `source_level` field is critical for multi-level evolution:

```python
# In _acquire_scope()
candidate["level"] = node.level  # Preserve original level

# In EvidenceEvolutionEngine
evolution_result.candidates[i]["source_level"] = source_level

# In ReflectionEngine
proposal["source_level"] = candidate["source_level"]
proposal["target_level"] = candidate["source_level"] + 1
```

## 11. Architecture Notes

### 11.1 Why Split EvidenceEvolution from Reflection?

**Current Problem**:
- ReflectionEngine mixes extraction and reasoning
- Boundary between "what is" and "what should be" is blurred
- Testing and maintenance complexity

**Solution**:
- EvidenceEvolutionEngine: Pure extraction (Information Extraction)
- ReflectionEngine: Pure reasoning (Decision Making)
- Clear separation of concerns

### 11.2 Fact as Internal Artifact

**Current Implementation**:
- `_extract_facts()` returns facts
- Facts are intermediate output
- Facts are NOT persisted

**Design Intent**:
- Facts are EvidenceEvolution internal working product
- Facts flow: Evidence → LLM → Facts → Candidate
- Facts are transient, Candidate is persistent

**Justification**:
- Storing Facts would duplicate Candidate content
- Facts are implementation detail of extraction
- Only Candidate needs to be queryable

### 11.3 Evidence Evolution vs Reflection

| Aspect | Evidence Evolution | Reflection |
|--------|-------------------|------------|
| **Question** | What information is in this evidence? | What should we do with this candidate? |
| **Output** | Structured candidate | Decision (Create/Refine/Split/Reject) |
| **LLM Role** | Extraction | Reasoning |
| **Deterministic** | Partially (LLM involved) | Yes (rule-based) |
| **Persistence** | Candidate saved | Proposal saved |
